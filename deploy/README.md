# Установка на сервер

> **Это для отдельного сервера, а не для сервера с VPN.**
>
> Скрипт исходит из того, что 80 и 443 свободны и nginx — входная точка.
> На сервере с панелью (Hiddify, Marzban, 3x-ui, Remnawave) эти порты
> держит она и перегенерирует свои конфигурации сама, поэтому
> `install.sh` там останавливается и ничего не делает.
>
> Причина не только в портах: продающий домен и рабочая нода не должны
> делить IP — блокировка одного заберёт с собой другое.
>
> Сайт сам по себе сервера не требует: он статический, и выкладывается
> на GitHub Pages — см. `site/README.md`. Приём оплаты сервера тоже
> не требует: он работает на Cloudflare Workers — см. `worker/README.md`.
>
> Эта папка нужна, только если вы всё же хотите держать чекаут
> на собственном сервере. Логика у обоих вариантов общая: `worker/`
> импортирует те же модули из `checkout/src/`, чтобы две копии кода,
> считающего деньги, не разошлись.

Два скрипта: первичная установка и обновление. Рассчитаны на Debian
и Ubuntu. Оба идемпотентные — повторный запуск ничего не ломает.

## Что нужно заранее

1. **A-запись** домена `hollvpn.ru` (и `www`) на IP сервера. Без этого
   всё поставится, но сертификат не выпустится — скрипт скажет об этом
   и продолжит.
2. **Доступ root** по SSH.
3. Свободный порт **8080**. Если занят ботом или панелью — задайте другой
   переменной `PORT`.

Скрипт ничего не удаляет за пределами своих папок и не трогает чужие
конфигурации nginx, так что бот на том же сервере не пострадает.

## Установка

```bash
ssh root@ВАШ_СЕРВЕР

apt-get update && apt-get install -y git
git clone -b claude/hollvpn-website-3d-k9507m \
  https://github.com/neverdeadsd-sketch/tg-bot.git /tmp/hollvpn
sudo bash /tmp/hollvpn/deploy/install.sh
```

Если порт 8080 занят:

```bash
sudo PORT=8090 bash /tmp/hollvpn/deploy/install.sh
```

Что произойдёт:

| Шаг | Куда |
|---|---|
| Node 22, nginx, certbot | ставятся, если их нет |
| Код | `/opt/hollvpn` |
| Сайт | `/var/www/hollvpn` |
| Служба | `hollvpn-checkout` в systemd |
| nginx | `/etc/nginx/sites-available/hollvpn`, прежний сохраняется как `.bak` |
| Сертификат | Let's Encrypt, если домен уже указывает на сервер |
| `.env` | создаётся из шаблона; **существующий не перезаписывается** |

Сайт откроется сразу. Оплата — нет: скрипт напечатает, чего не хватает
в `.env`, и служба останется остановленной, пока вы не заполните.

## Что заполнить руками

Проще всего — скриптом с вопросами:

```bash
sudo bash /opt/hollvpn/deploy/set-env.sh
```

Он спросит по очереди, что нужно, покажет уже заполненное в замаскированном
виде (Enter — оставить как есть), проверит, что всё на месте, и сам запустит
службу. Секреты вводятся скрыто и **не попадают в историю оболочки** —
в отличие от варианта, где их передают аргументом команды.

Что он спросит:

| Значение | Где взять |
|---|---|
| `YOOKASSA_SECRET_KEY` | Кабинет ЮKassa → «Интеграция» → «Ключи API» |
| `TELEGRAM_BOT_TOKEN` | @BotFather |
| `TELEGRAM_ADMIN_CHAT_ID` | @userinfobot ответит числом |
| `FULFILMENT_URL` | Адрес в боте для автовыдачи; можно позже |

Нужен ключ ЮKassa и хотя бы один способ сообщить об оплате — Telegram
или эндпоинт бота. Без этого служба не запустится.

### Если предпочитаете редактор

```bash
sudo nano /opt/hollvpn/checkout/.env
```

Сохранить: <kbd>Ctrl</kbd>+<kbd>O</kbd>, <kbd>Enter</kbd>, выйти:
<kbd>Ctrl</kbd>+<kbd>X</kbd>. Если `nano` нет — `apt-get install -y nano`.
После правки:

```bash
sudo systemctl restart hollvpn-checkout
sudo systemctl status hollvpn-checkout
```

## Если домен ещё не указывает на сервер

Установка пройдёт, сайт поднимется, но сертификата не будет — и снаружи
ничего не откроется. Признак: `curl` со своего компьютера отвечает
`Could not resolve host`.

Узнайте IP сервера и заведите A-записи у регистратора домена:

```bash
curl -4 ifconfig.me
```

| Тип | Имя | Значение |
|---|---|---|
| A | `@` | IP из команды выше |
| A | `www` | тот же IP |

Записи заводятся там, куда указывают NS-серверы домена: это может быть
и не тот регистратор, у которого домен куплен.

Когда разойдётся (обычно минуты, иногда часы):

```bash
sudo bash /opt/hollvpn/deploy/enable-https.sh
```

Скрипт сам проверит, что домен указывает именно на этот сервер и что
файл-проверка отдаётся по HTTP, и только тогда выпустит сертификат — иначе
certbot падает с ошибкой, по которой причину не угадать. Проверить,
разошлось ли: `getent ahostsv4 hollvpn.ru`.

certbot здесь работает в режиме `certonly --webroot`: он только кладёт
файл-проверку в корень сайта и забирает сертификат. Конфигурацию nginx
пишет сам скрипт и применяет её через `reload`, а не `restart`. Это
важно на сервере, где за тем же nginx стоит бот: `reload` не переоткрывает
слушающий сокет, поэтому уронить nginx ошибкой вида
`bind() to 0.0.0.0:80 failed (98: Address already in use)` он не может,
а если nginx новую конфигурацию не примет — скрипт вернёт прежнюю
и ничего не изменится.

Продление сертификата настраивается там же: таймер certbot обновляет его
сам и перезагружает nginx. Проверить, что продление пройдёт:
`sudo certbot renew --dry-run`.

## Проверка перед первой продажей

```bash
# служба жива
systemctl status hollvpn-checkout
curl localhost:8080/health          # {"status":"ok","stranded_orders":0}

# уведомления доходят
sudo bash /opt/hollvpn/deploy/test-notify.sh

```

Последняя проверка — **со своего компьютера, а не с сервера**: она смотрит,
доступен ли API снаружи.

Linux или macOS:

```bash
curl -i https://hollvpn.ru/api/payment/test
```

Windows, PowerShell — именно `curl.exe`, потому что `curl` там подменён
на `Invoke-WebRequest` с другими ключами:

```powershell
curl.exe -i https://hollvpn.ru/api/payment/test
```

Ждём `404` и `{"error":"Заказ не найден"}`. Это важнее, чем кажется:
одной командой проверяется вся цепочка — DNS, сертификат, nginx
и проксирование `/api`. Если вместо 404 ошибка соединения, то и ЮKassa
до вебхука не достучится, и оплаты будут проходить без выдачи подписки.

`set-env.sh` отправляет пробное сообщение сам, сразу после настройки
Telegram. Неверный токен обнаружится там же, а не в момент, когда деньги
пришли, а сообщения нет.

## Обновление

```bash
sudo bash /opt/hollvpn/deploy/update.sh
```

Забирает изменения, **прогоняет тесты** и только потом обновляет сайт
и перезапускает службу. Если тесты не прошли — обновление останавливается,
рабочая версия продолжает работать на прежнем коде.

## Если что-то не так

```bash
systemctl status hollvpn-checkout        # работает ли служба
journalctl -u hollvpn-checkout -n 50     # что она пишет
journalctl -u hollvpn-checkout -f        # смотреть в реальном времени
nginx -t                                 # цела ли конфигурация nginx
curl localhost:8080/health               # отвечает ли чекаут
```

`/health` возвращает **503**, если есть оплаченные заказы без выданной
подписки. Это не поломка сервиса, а сигнал: деньги получены, доступ нет,
нужно разобраться вручную. Стоит завести в мониторинг.

## Что скрипт делает с безопасностью

- Служба работает под отдельным пользователем `hollvpn`, не под root.
- `.env` доступен только владельцу (`chmod 600`).
- systemd-юнит с `ProtectSystem=strict`, `ProtectHome`, `NoNewPrivileges`:
  служба может писать только в свою папку.
- `TRUST_PROXY=true` проставляется автоматически, иначе чекаут увидит адрес
  nginx вместо адреса ЮKassa и отклонит все уведомления об оплате.

Секретный ключ ЮKassa попадает только в `.env` на сервере. В репозитории
его нет и быть не должно.
