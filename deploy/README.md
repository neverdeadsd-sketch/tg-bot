# Установка на сервер

Два скрипта: первичная установка и обновление. Рассчитаны на Debian
и Ubuntu. Оба идемпотентные — повторный запуск ничего не ломает.

## Что нужно заранее

1. **A-запись** домена `hollvpn.online` (и `www`) на IP сервера. Без этого
   всё поставится, но сертификат не выпустится — скрипт скажет об этом
   и продолжит.
2. **Доступ root** по SSH.
3. Свободный порт **8080**. Если занят ботом или панелью — задайте другой
   переменной `PORT`.

Скрипт ничего не удаляет за пределами своих папок и не трогает чужие
конфигурации nginx, так что бот на том же сервере не пострадает.

## Установка

```bash
ssh root@ВАШ_СЕРВЕР

apt-get update && apt-get install -y git
git clone -b claude/hollvpn-website-3d-k9507m \
  https://github.com/neverdeadsd-sketch/tg-bot.git /tmp/hollvpn
sudo bash /tmp/hollvpn/deploy/install.sh
```

Если порт 8080 занят:

```bash
sudo PORT=8090 bash /tmp/hollvpn/deploy/install.sh
```

Что произойдёт:

| Шаг | Куда |
|---|---|
| Node 22, nginx, certbot | ставятся, если их нет |
| Код | `/opt/hollvpn` |
| Сайт | `/var/www/hollvpn` |
| Служба | `hollvpn-checkout` в systemd |
| nginx | `/etc/nginx/sites-available/hollvpn`, прежний сохраняется как `.bak` |
| Сертификат | Let's Encrypt, если домен уже указывает на сервер |
| `.env` | создаётся из шаблона; **существующий не перезаписывается** |

Сайт откроется сразу. Оплата — нет: скрипт напечатает, чего не хватает
в `.env`, и служба останется остановленной, пока вы не заполните.

## Что заполнить руками

```bash
nano /opt/hollvpn/checkout/.env
```

- `YOOKASSA_SECRET_KEY` — кабинет ЮKassa → «Интеграция» → «Ключи API».
- `FULFILMENT_URL` — адрес в вашем боте, который принимает POST об оплате
  и выдаёт подписку. Формат запроса — в `checkout/README.md`.

Остальное скрипт проставил сам: `PUBLIC_URL`, `PORT`, `TRUST_PROXY=true`
и путь к базе.

Потом:

```bash
systemctl start hollvpn-checkout
systemctl status hollvpn-checkout
curl localhost:8080/health
```

## Обновление

```bash
sudo bash /opt/hollvpn/deploy/update.sh
```

Забирает изменения, **прогоняет тесты** и только потом обновляет сайт
и перезапускает службу. Если тесты не прошли — обновление останавливается,
рабочая версия продолжает работать на прежнем коде.

## Если что-то не так

```bash
systemctl status hollvpn-checkout        # работает ли служба
journalctl -u hollvpn-checkout -n 50     # что она пишет
journalctl -u hollvpn-checkout -f        # смотреть в реальном времени
nginx -t                                 # цела ли конфигурация nginx
curl localhost:8080/health               # отвечает ли чекаут
```

`/health` возвращает **503**, если есть оплаченные заказы без выданной
подписки. Это не поломка сервиса, а сигнал: деньги получены, доступ нет,
нужно разобраться вручную. Стоит завести в мониторинг.

## Что скрипт делает с безопасностью

- Служба работает под отдельным пользователем `hollvpn`, не под root.
- `.env` доступен только владельцу (`chmod 600`).
- systemd-юнит с `ProtectSystem=strict`, `ProtectHome`, `NoNewPrivileges`:
  служба может писать только в свою папку.
- `TRUST_PROXY=true` проставляется автоматически, иначе чекаут увидит адрес
  nginx вместо адреса ЮKassa и отклонит все уведомления об оплате.

Секретный ключ ЮKassa попадает только в `.env` на сервере. В репозитории
его нет и быть не должно.
