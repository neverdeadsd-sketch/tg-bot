# Архив удалённых сообщений

Телеграм-бот, который запоминает сообщения в чатах и сообщает, когда сообщение
удаляют: присылает в архивный чат его текст, автора, время и вложение.

aiogram 3 · SQLite · Python 3.11+

---

## Сначала — про ограничение Telegram

**Bot API не сообщает об удалении сообщений.** Такого события не существует:
бот не может узнать, что сообщение удалили, тем же способом, каким узнаёт о новом
сообщении. Это ограничение самого Telegram, а не недоделка в коде.

Поэтому режимов два, и выбор между ними — это выбор между «обычный бот, но с
задержкой» и «мгновенно, но нужен вход в аккаунт».

|                        | Режим 1: бот                                   | Режим 2: аккаунт                           |
|------------------------|------------------------------------------------|--------------------------------------------|
| Команда запуска        | `python bot.py`                                | `python userbot.py`                        |
| Что нужно              | токен от [@BotFather](https://t.me/BotFather)  | вход в аккаунт: `api_id`, `api_hash`, телефон |
| Какие чаты видит       | только те, куда добавлен бот                   | все чаты аккаунта, включая личные          |
| Как узнаёт об удалении | сам переспрашивает Telegram по расписанию      | Telegram присылает событие                 |
| Задержка               | от ~45 секунд до 3 часов, зависит от возраста сообщения | мгновенно                         |
| Точность времени       | известен момент обнаружения, не самого удаления | точное время удаления                     |
| Оговорки               | нет, это обычный бот                           | автоматизация личного аккаунта — на ваш страх и риск |

Оба режима пишут в одну базу, и запускать их можно вместе.

## Быстрый старт (режим 1)

```bash
cp .env.example .env     # вписать BOT_TOKEN и ADMIN_IDS
pip install -r requirements.txt
python bot.py
```

Дальше — подключить чаты:

1. **Создайте архивный чат.** Приватный канал или группу, куда бот будет
   присылать удалённое. Добавьте туда бота, отправьте в чат `/id` и впишите
   полученное число в `ARCHIVE_CHAT_ID`. Без этого удалённые сообщения всё равно
   сохраняются — смотреть их командой `/recent`.

2. **Добавьте бота в чат, за которым нужно следить.**

3. **Отключите режим приватности.** У [@BotFather](https://t.me/BotFather):
   `/setprivacy` → выбрать бота → **Disable**. Без этого бот видит в группах
   только команды, обращённые к нему, и архивировать ему нечего. После смены
   настройки бота нужно удалить из чата и добавить заново.
   Если забыть — бот скажет об этом в логе при запуске.

4. **Для канала** добавьте бота администратором.

Бот запоминает только то, что увидел сам: сообщения, отправленные до его
добавления в чат, восстановить невозможно.

---

## Команды

Отвечают в личке и только тем, кто указан в `ADMIN_IDS` — архив чужой переписки
не должен открываться любому желающему.

| Команда        | Что делает                                       |
|----------------|--------------------------------------------------|
| `/recent [N]`  | последние удалённые сообщения (по умолчанию 5)    |
| `/find текст`  | поиск по текстам удалённых сообщений              |
| `/stats`       | сколько сохранено, сколько под наблюдением        |
| `/export [N]`  | выгрузка в JSON файлом                            |
| `/id`          | id текущего чата — работает в любом чате          |

## Режим 2: наблюдение с аккаунта

Ловит удаления сразу и во всех чатах, включая личные.

```bash
pip install -r requirements-userbot.txt
# в .env добавить TELEGRAM_API_ID и TELEGRAM_API_HASH
python userbot.py
```

`api_id` и `api_hash` выдают на [my.telegram.org](https://my.telegram.org) →
API development tools. При первом запуске спросит телефон и код из Telegram.

Отчёты уходят в `ARCHIVE_CHAT_ID`, а если он не задан — в «Избранное».

Файл сессии (`data/userbot.session`) равнозначен паролю от аккаунта вместе со
вторым фактором: он лежит в `data/`, который закрыт `.gitignore`.

Учтите: автоматизация личного аккаунта — это не то же самое, что бот. Telegram
такие клиенты не запрещает, но и гарантий не даёт.

## Как бот замечает удаление (режим 1)

Поскольку события об удалении нет, бот спрашивает Telegram окольным путём:
просит **снять клавиатуру с чужого сообщения**. Такую правку Telegram не
разрешит никогда, но ответ на запрос различается:

| Ответ Telegram               | Вывод                      |
|------------------------------|----------------------------|
| `message can't be edited`    | сообщение на месте         |
| `message to edit not found`  | сообщения больше нет       |
| `chat not found`, `bot was kicked` | чат недоступен целиком |

Само сообщение при этом не меняется: правка не проходит, меняется только текст
ошибки. Незнакомый ответ считается живым сообщением — ложный отчёт об удалении
хуже пропущенного, его уже не отозвать.

**Расписание проверок.** Частота зависит от возраста сообщения, потому что
удаляют почти всегда сразу после отправки:

| Возраст сообщения | Проверка раз в |
|-------------------|----------------|
| до 10 минут       | 45 секунд      |
| до 2 часов        | 5 минут        |
| до суток          | 30 минут       |
| дальше            | 3 часа         |

Через `WATCH_HOURS` (по умолчанию 48 часов) наблюдение снимается. Частота
запросов ограничена `PROBE_RATE` (по умолчанию 2 в секунду), на ответ «подождите»
бот выдерживает паузу.

### Чего режим 1 не поймает

- **Сообщение, удалённое позже `WATCH_HOURS`** — наблюдение к тому времени снято.
- **Кто именно удалил.** Bot API этого не сообщает, видно только, что сообщения
  нет. По той же причине в отчёте стоит «замечено удалённым», а не «удалено»:
  точное время известно лишь в режиме 2.
- **Сообщения до добавления бота** в чат.
- **Чужую личную переписку** — бот видит только свои чаты. Для личных чатов
  аккаунта нужен режим 2.
- **Сообщения со своей клавиатурой** бот архивирует, но не проверяет: такую
  правку Telegram бы выполнил и клавиатуру испортил. Это сообщения ботов,
  у сообщений людей клавиатуры не бывает.

## Настройки

Всё — через `.env`, пример лежит в `.env.example`.

| Переменная                 | По умолчанию | Назначение                                        |
|----------------------------|--------------|---------------------------------------------------|
| `BOT_TOKEN`                | —            | токен от @BotFather, обязателен                   |
| `ARCHIVE_CHAT_ID`          | —            | куда присылать удалённое; пусто — только в базу    |
| `ADMIN_IDS`                | —            | кому доступны команды; пусто — никому              |
| `DATA_DIR`                 | `data`       | где лежат база и вложения                          |
| `DOWNLOAD_MEDIA`           | `true`       | скачивать вложения или хранить только `file_id`    |
| `MAX_DOWNLOAD_MB`          | `20`         | предел размера вложения (у Bot API это максимум)   |
| `WATCH_HOURS`              | `48`         | сколько следить за сообщением                      |
| `PROBE_RATE`               | `2.0`        | проверок в секунду                                 |
| `PROBE_BATCH`              | `40`         | размер пачки проверок                              |
| `KEEP_DAYS`                | `0`          | срок хранения архива; `0` — бессрочно              |
| `WATCH_CHATS`              | —            | следить только за этими чатами                     |
| `IGNORE_CHATS`             | —            | не следить за этими чатами                         |
| `ARCHIVE_SERVICE_MESSAGES` | `false`      | архивировать ли «вошёл в группу» и подобное        |
| `TELEGRAM_API_ID`, `TELEGRAM_API_HASH` | — | только для режима 2                      |

Про `DOWNLOAD_MEDIA`: ссылка `file_id` обычно продолжает работать и после
удаления сообщения, но гарантии на это нет. Единственный надёжный способ
сохранить вложение — забрать файл сразу, поэтому по умолчанию бот так и делает.

## Где что лежит

```
bot.py              запуск режима 1
userbot.py          запуск режима 2
config.py           чтение .env
app/
  archiver.py       приём сообщений и правок
  probe.py          «жив ли ещё этот message_id»
  watcher.py        фоновый обход очереди проверок
  schedule.py       как часто проверять сообщение
  limiter.py        ограничение частоты запросов
  storage.py        SQLite: сообщения, версии текста, очередь
  reporter.py       отчёт об удалённом сообщении
  media.py          вложения
  handlers/commands.py  команды бота
data/
  archive.db        база
  media/            скачанные вложения
```

Кроме удалённых, бот хранит **версии исправленных** сообщений: если сообщение
правили, а потом удалили, в отчёт попадут и прежние варианты текста.

## Хранение и приватность

Архив — это переписка людей. База и вложения лежат в `data/`, который закрыт
`.gitignore`, и больше никуда не отправляются. Доступ к командам ограничен
`ADMIN_IDS`; пустой список означает, что бот не отвечает никому.

В ряде стран запись чужих сообщений без ведома участников переписки ограничена
законом. Предупредите участников чата и отвечайте за собранные данные сами.

Срок хранения задаётся `KEEP_DAYS` — записи старше удаляются вместе с правками
и чистятся раз в час.

## Тесты

```bash
pip install -r requirements-dev.txt
pytest
```

96 тестов, Telegram не требуется: запросы к API подменены, время в проверках
частоты — тоже, поэтому набор проходит за секунды.

Покрыто то, что нельзя увидеть без настоящего Telegram: разбор ответов на
проверку живости, расписание и ограничение частоты, нарезка длинных отчётов под
лимит сообщения, однократность отчёта об одном удалении, повторная отправка
недоставленного отчёта.

cp .env.example .env     # заполнить

`data/` и `logs/` подключены как тома — архив переживает пересборку образа.
