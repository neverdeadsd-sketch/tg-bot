# tgnames

Бот-скрипт, который ищет и оценивает потенциально ценные юзернеймы Telegram
(короткие, словарные, «красивые» по структуре), проверяет их занятость через
официальный API и занимает свободные — создавая под каждый публичный канал.

Занять юзернейм каналом — единственный штатный способ держать больше одного
публичного адреса на аккаунте: у самого аккаунта юзернейм один, а каналов
может быть несколько.

```
генерация кандидатов -> офлайн-оценка -> проверка занятости -> захват каналом
   generate              scoring          scan                 claim
```

## Установка

Нужен **Python 3.11 или новее** (используется `tomllib` из стандартной
библиотеки). Проверить свою версию: `python --version`.

Код лежит в ветке `claude/telegram-username-analyzer-bot-8ks7fm` — при
клонировании её нужно указать явно, иначе скачается пустой `main`.

### Windows (PowerShell)

```powershell
cd $HOME
git clone -b claude/telegram-username-analyzer-bot-8ks7fm https://github.com/neverdeadsd-sketch/tg-bot.git
cd tg-bot

python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt

copy .env.example .env
copy config.example.toml config.toml
```

Дальше вызывайте интерпретатор из venv напрямую — так не нужно возиться с
`Activate.ps1` и политикой выполнения PowerShell:

```powershell
.\.venv\Scripts\python.exe run.py analyze money
```

Если git не установлен — можно скачать [ZIP-архив ветки][zip], распаковать и
начать с шага `python -m venv .venv`.

[zip]: https://github.com/neverdeadsd-sketch/tg-bot/archive/refs/heads/claude/telegram-username-analyzer-bot-8ks7fm.zip

### Linux / macOS

```bash
git clone -b claude/telegram-username-analyzer-bot-8ks7fm https://github.com/neverdeadsd-sketch/tg-bot.git
cd tg-bot

python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

```

### Ключи API

`api_id` и `api_hash` берутся на <https://my.telegram.org> → *API development
tools* и вписываются в `.env`. Первый вход создаёт файл сессии:

```bash
python run.py login
```

Команда `analyze` работает и без ключей — она полностью офлайновая. Ключи
нужны только для `scan`, `claim`, `hunt`, `login` и `inventory`.

### Если мало места на диске

Половина инструмента вообще не нуждается в зависимостях — только стандартная
библиотека Python. Без venv и без `pip install` работают:

`analyze`, `generate`, `list`, `stats`, `export` и `claim` без `--execute`.

Это ~1.3 МБ на репозиторий и ноль сверху:

```powershell
git clone -b claude/telegram-username-analyzer-bot-8ks7fm https://github.com/neverdeadsd-sketch/tg-bot.git
cd tg-bot
python run.py analyze money
python run.py generate -s all -n 500
python run.py claim -n 3          # dry-run, покажет что занял бы
```

Telethon (≈58 МБ вместе с venv) нужен только чтобы реально ходить в Telegram:
`scan`, `claim --execute`, `hunt`, `login`, `inventory`. Без него эти команды
не падают трейсбеком, а объясняют, чего не хватает.

### Проверка занятости без ключей: `scan --web`

Если `api_id`/`api_hash` получить не удаётся (форма на my.telegram.org
регулярно отдаёт пустой `ERROR`), занятость можно определять по публичным
страницам `t.me` — без ключей, без Telethon, на одной стандартной библиотеке:

```bash
python run.py scan --web --calibrate-only              # сначала самопроверка
python run.py scan --web --calibrate-only --control мойканал  # со своим контролем
python run.py scan --web -n 50
```

Разметку этих страниц Telegram не документирует и меняет когда захочет,
поэтому признаки не зашиты в код, а **выясняются на месте**. Перед работой
чекер запрашивает имена с заведомо известным статусом — занятые (`@durov`,
`@telegram`, `@botfather` — намеренно разные по устройству страницы) и длинные
случайные строки, которых существовать не может.

Главное правило: **вывод «свободно» требует доказательства, а не отсутствия
улик.** Занятые страницы бывают очень разными — пользователь без аватара, бот,
группа, — а при троттлинге ответ вообще приходит урезанным и не содержит
никаких признаков. Поэтому логика перевёрнута:

* свободным считается только то, что **точно совпало** с эталоном пустой
  страницы (все свободные страницы одинаковы — это надёжная сторона);
* занятым — всё, где есть хоть один признак, которого на пустой странице
  не бывает;
* всё остальное — `unknown`, полноправный ответ, а не «наверное свободно».

Дополнительные защиты от троттлинга, из-за которого ответы тихо портятся:
ответ короче 600 байт не может быть вердиктом вообще; четыре непонятных ответа
подряд или HTTP 429 останавливают прогон; каждые 25 проверок калибровка
перепроверяется на свежем заведомо свободном имени, и при расхождении прогон
прекращается, чтобы в базу не попало ни одного сомнительного вердикта.

Можно подать свои контрольные имена — например то, которое чекер определил
неверно: `--control мойканал`. Если на нём калибровка не сойдётся, вы узнаете
об этом до того, как получите хоть один вердикт.

### Чего веб-проверка не умеет в принципе

Она отвечает на вопрос «есть ли у имени владелец», а не «можно ли его занять».
Это разные вопросы, и разница существенная.

Telegram **придерживает короткие осмысленные слова** — `elite`, `money`,
`level` — и продаёт их через аукцион Fragment. Владельца у них нет, страница
`t.me/elite` выглядит ровно как у свободного имени, и никакая проверка по
странице этого не различит. Через API различие видно: там приходит отдельный
ответ `USERNAME_PURCHASE_AVAILABLE`, и такие имена получают статус
`purchasable`.

Поэтому веб-проверка не ставит статус `available` вообще. Её положительный
вердикт — `unclaimed`, что читается как «владельца не видно, занимаемость не
проверена». Статус `available` появляется только после проверки через API.

Плюс офлайновый признак: короткие словарные слова получают тег
`likely-reserved`. Это априорная оценка, а не вердикт о конкретном имени, но
она сразу показывает, какие из `unclaimed` почти наверняка недоступны.

`claim` перед созданием канала всё равно перепроверяет занятость через API,
поэтому попытка занять зарезервированное имя не тратится впустую — приходит
`purchasable`, и имя помечается соответственно.

### Полный цикл без ключей вообще

Автоматический захват без `api_id` невозможен — создание канала есть только в
API. Но занять юзернейм можно руками в приложении Telegram, это три касания:
**создать канал → тип «публичный» → вписать имя**. Ключи для этого не нужны.

Тогда цикл выглядит так:

```bash
python run.py generate -s all -n 500          # набрать и оценить кандидатов
python run.py scan --web -n 50                # отсеять занятые, без ключей
python run.py list --status available -n 30   # список к захвату
# ... занять понравившиеся руками в приложении ...
python run.py mark goldvault --note "создан вручную"
```

`mark` записывает результат в базу, чтобы имя больше не предлагалось и учёт
оставался сходящимся. Ручной захват ничем не хуже автоматического — разница
только в скорости.

## Быстрый старт

```bash
# 1. Оценить конкретные юзернеймы — интернет не нужен вообще
python run.py analyze money t.me/lunar @crypto777 my_long_handle_2019

# 2. Сгенерировать и отобрать 500 лучших кандидатов в базу
python run.py generate -s all -n 500

# 3. Проверить занятость первых 50 через Telegram
python run.py scan -n 50

# 4. Посмотреть, что свободно (ничего не создаётся — это dry-run)
python run.py claim -n 3

# 5. Реально занять
python run.py claim -n 3 --execute
```

Всё сразу — `python run.py hunt -n 50 --claim-limit 3 --execute`.

## Команды

| Команда | Что делает |
|---|---|
| `analyze` | Офлайн-оценка юзернеймов. `--explain` покажет разбор по факторам, `--json` — машинный вывод |
| `generate` | Генерирует кандидатов стратегией, оценивает и складывает лучших в базу |
| `scan` | Проверяет занятость очереди через Telegram. `--web` — без ключей, по страницам t.me |
| `claim` | Занимает свободные юзернеймы, создавая канал под каждый. **По умолчанию dry-run** |
| `hunt` | `generate` + `scan` + `claim` за один проход |
| `mark` | Ставит статус вручную — для имён, занятых прямо в приложении Telegram |
| `list` | Показывает содержимое базы, можно фильтровать `--status` |
| `stats` | Сводка по базе и остаток квот |
| `export` | Выгрузка в CSV/JSON |
| `login` | Первый вход, создаёт файл сессии |
| `inventory` | Публичные каналы аккаунта, то есть уже занятые адреса |

## Как считается ценность

`analyze` даёт оценку 0–100 и тир (S/A/B/C/D/F). Итог — взвешенная сумма пяти
независимых сигналов, каждый из которых нормирован к 0–100:

| Сигнал | Вес | Что измеряет |
|---|---|---|
| `length` | 0.36 | Длина. Главный ценовой фактор: 5 символов — потолок, дальше резкий спад |
| `charset` | 0.14 | Только буквы дорого; цифры дешевле, подчёркивания дешевле всего |
| `lexical` | 0.22 | Реальное слово из словаря, составное из двух слов, или мусор |
| `pattern` | 0.18 | Повторы (`aaaaa`), периодичность (`abab`), ряды (`abcde`), палиндромы, репдигиты |
| `phonetic` | 0.10 | Читается ли вслух: доля гласных, чередование, стечения согласных |

Дальше применяются множители: зарезервированные слова и торговые марки
(`telegram`, `apple`) режутся до 25%, рискованные подстроки — до 20%, суффикс
`bot` — до 70%, а короткое чистое словарное слово получает бонус. Сильный
паттерн частично замещает словарный и фонетический сигналы — `aaaaa` не обязано
быть словом, чтобы быть ценным.

```
$ python run.py analyze goldbank --explain

@goldbank
  score 61.03  tier B  band $$ (rough resale $50-250)
  components: length=61, charset=100, lexical=82, pattern=15, phonetic=43
  tags: common, premium
    - length 8
    - letters only
    - compound of gold+bank
```

Столбец `band` — грубая прикидка порядка цены для сортировки очереди,
а не котировка. Реальная цена зависит от спроса на конкретное слово.

Словари лежат в `tgnames/data/*.txt` — обычные текстовые файлы, их можно
пополнять под свою нишу.

## Стратегии генерации

| Стратегия | Пример вывода |
|---|---|
| `words` | Словарные слова: `money`, `vault`, `lunar` |
| `combos` | Префикс/суффикс к слову: `thevault`, `goldhq`, `tonpay` |
| `compounds` | Склейка двух слов: `goldbank`, `cryptoshop` |
| `patterns` | Структурные: `aaaaa`, `ababa`, `abcde`, `a7777` |
| `brandables` | Произносимые CVCV-бренды: `rivo`, `kalum`, `zenta` |
| `numeric` | Слово + красивое число: `gold777`, `ton100` |
| `all` | Всё вместе (~156k кандидатов) |

Отдельно: `--file seeds.txt` — свой список, `--mutate vault gold` — вариации
вокруг понравившихся адресов (`vaults`, `thevault`, `vaultpay`, замены букв).

## Лимиты и безопасность

Это главная часть, а не приписка: Telegram жёстко ограничивает создание
публичных каналов и наказывает всплески FloodWait'ом.

* **Dry-run по умолчанию.** `claim` без `--execute` ничего не создаёт. С
  `--execute` и без `-y` он ещё раз спросит подтверждение.
* **Лимит публичных ссылок.** У обычного аккаунта их 10, с Premium больше.
  Упёршись в него, бот получает `CHANNELS_ADMIN_PUBLIC_TOO_MUCH`, аккуратно
  удаляет пустой канал и останавливает прогон. `inventory` показывает, сколько
  слотов занято.
* **Персистентные квоты.** Часовые и суточные счётчики лежат в SQLite, поэтому
  перезапуск процесса их не обнуляет. По умолчанию 5 захватов в час и 20 в
  сутки, проверок — 400 в час.
* **FloodWait.** Короткий бот пережидает, длиннее `max_floodwait_seconds`
  (300 с) — останавливает прогон, а не долбится дальше.
* **Перепроверка перед захватом.** Очередь может быть многочасовой давности,
  поэтому непосредственно перед созданием канала занятость проверяется заново.
* **Уборка за собой.** Если юзернейм не прицепился, созданный канал удаляется
  (`channel.delete_on_failure`).
* **Чёрный список.** Торговые марки, официальные имена Telegram и рискованные
  подстроки помечаются тегами `reserved` / `risky` и по умолчанию исключаются
  через `selection.exclude_tags`.

Стоит понимать: Telegram может отозвать публичный юзернейм у неактивного
канала, а массовый сквоттинг противоречит его правилам. Консервативные
дефолты выше стоят там не для красоты — поднимать их означает менять
FloodWait на бан, а не получать больше адресов. Часть коротких и «красивых»
адресов вообще не выдаётся бесплатно: на них API отвечает
`USERNAME_PURCHASE_AVAILABLE`, то есть продаются они только через аукцион
Fragment — бот помечает такие статусом `purchasable` и не трогает.

## Конфигурация

`config.toml` (см. `config.example.toml`); переменные окружения из `.env`
приоритетнее файла.

```toml
[limits]
checks_per_minute = 20.0
claims_per_hour = 5
claims_per_day = 20
max_floodwait_seconds = 300
claim_cooldown_seconds = 45.0

[channel]
title_template = "@{username}"
about_template = "Reserved."
delete_on_failure = true

[selection]
min_score = 60.0
exclude_tags = ["reserved", "reserved-part", "risky", "noise"]
```

## Статусы кандидатов

`new` → проверен → `available` / `unclaimed` / `taken` / `purchasable` /
`invalid`, и после захвата `claimed` либо `failed`. `available` ставит только
проверка через API; веб-проверка ставит более слабый `unclaimed`. Всё хранится в SQLite (`data/tgnames.db`)
вместе с журналом событий, так что прогон можно продолжить с того же места.

## Структура

```
tgnames/
  scoring.py     оценка ценности (чистые функции, без сети)
  generator.py   стратегии генерации кандидатов
  wordlists.py   загрузка словарей из data/
  client.py      Telethon: проверка занятости и захват каналом
  webcheck.py    самокалибрующаяся проверка занятости по t.me, без ключей
  ratelimit.py   token bucket + персистентные квоты
  storage.py     SQLite: кандидаты, события, счётчики
  config.py      TOML + переменные окружения
  cli.py         командный интерфейс
  data/          словари, аффиксы, стоп-листы
tests/           163 теста, Telegram замокан — аккаунт не нужен
```

## Тесты

```bash
pip install pytest pytest-asyncio
python -m pytest tests -q
```

Сетевой слой покрыт моками: проверяются маппинг ошибок API, поведение при
FloodWait, удаление канала при неудаче, остановка на лимите публичных ссылок
и перепроверка перед захватом. Реальный аккаунт для тестов не требуется.
