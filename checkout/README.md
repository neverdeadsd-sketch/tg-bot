# Чекаут HollVPN

Оплата подписки на сайте через ЮKassa. Node без единой внешней зависимости:
HTTP на `node:http`, база на `node:sqlite`, запросы к API через встроенный
`fetch`. `npm install` не нужен.

```
checkout/
├── src/
│   ├── index.js      запуск
│   ├── config.js     переменные окружения + тарифы (источник цен)
│   ├── server.js     четыре маршрута
│   ├── yookassa.js   создание и чтение платежа
│   ├── store.js      заказы в SQLite
│   ├── fulfil.js     сообщение о выдаче с повторами
│   └── net.js        проверка адреса источника вебхука
└── test/checkout.test.js
```

## Запуск

```bash
cp .env.example .env      # заполнить YOOKASSA_SECRET_KEY и FULFILMENT_URL
node src/index.js
npm test                  # 12 тестов, сети не требуют
```

## Почему сервис не стартует без FULFILMENT_URL

Это сделано намеренно. Чекаут, который умеет принять деньги и не умеет выдать
подписку, — это способ собрать оплаты и не оказать услугу. Лучше не подняться,
чем подняться таким.

`FULFILMENT_URL` получает POST, когда оплата подтверждена:

```json
{
  "order_id": "b9817f0e-…",
  "payment_id": "2f2a…",
  "telegram": "@username",
  "days": 365,
  "amount_kopecks": 149900,
  "currency": "RUB",
  "paid_at": "2026-09-09T12:00:00.000Z"
}
```

Ответ 2xx означает «подписка выдана». Любой другой — сервис повторит четыре
раза с паузами 0/2/8/30 секунд, а затем пометит заказ как требующий ручной
выдачи: он попадёт в `GET /health` (тот начнёт отвечать 503) и в статус заказа
с флагом `needs_attention`. Деньги при этом уже получены — такие заказы
разбираются вручную, поэтому `/health` стоит завести в мониторинг.

Если `FULFILMENT_TOKEN` задан, он уходит в заголовке `Authorization: Bearer`.

## Что защищено и как

**Сумму называет сервер.** Клиент присылает только число дней; цена берётся
из `TERMS` в `config.js`. Запрос с `amount: "1.00"` для годовой подписки
создаст платёж на 1499 ₽ — это в тестах.

**Вебхуку не верят.** Из тела уведомления берётся только идентификатор
платежа, после чего статус перечитывается из API ЮKassa нашим ключом. Верим
только этому ответу, и дополнительно сверяем сумму с той, на которую
выставляли счёт. Подделать уведомление, не имея доступа к магазину, нельзя.

**Выдача происходит один раз.** Повторные уведомления о том же платеже — норма
для ЮKassa; заказ с проставленным `fulfilled_at` второй раз не выдаётся.

**Ключ идемпотентности — идентификатор заказа.** Пользователь, дважды нажавший
кнопку, не заплатит дважды.

**Адрес источника вебхука** сверяется со списком ЮKassa (`net.js`). Это не
основная защита, а отсечка мусора до логики. За обратным прокси включайте
`TRUST_PROXY=true` — иначе сервис увидит адрес nginx вместо адреса ЮKassa
и отклонит все настоящие уведомления. Заголовку `X-Real-IP` сервис верит
только при этом флаге: без него подделать источник смог бы кто угодно.

**Секретный ключ** живёт только в переменной окружения и в заголовке
`Authorization`. Он не попадает ни в логи, ни в ответы, ни в репозиторий.

## Маршруты

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/checkout` | `{days, telegram}` → `{order_id, confirmation_url}` |
| GET | `/api/payment/:orderId` | статус заказа для страницы возврата |
| POST | `/api/yookassa/webhook` | уведомление от ЮKassa |
| GET | `/health` | 200, либо 503 при невыданных оплаченных заказах |

На `/api/checkout` действует ограничение: 10 заказов с адреса в час.

## Настройка на стороне ЮKassa

1. В личном кабинете → «Интеграция» → «HTTP-уведомления» указать
   `https://hollvpn.online/api/yookassa/webhook`.
2. Включить события `payment.succeeded` и `payment.canceled`.
3. Секретный ключ выпустить там же и положить в `.env`. При компрометации —
   отозвать и выпустить новый; в репозитории его быть не должно никогда.

## Чек

`SEND_RECEIPT=false` по умолчанию. У самозанятого чек формируется в приложении
«Мой налог», а не в ЮKassa; передача `receipt` в магазин, не настроенный
на 54-ФЗ, приводит к ошибке создания платежа. Включать только если магазин
действительно настроен на передачу чеков через ЮKassa.

Формирование чека в «Мой налог» — обязанность продавца по ФЗ №&nbsp;422-ФЗ,
и этот сервис её не закрывает.

## Nginx

Сайт статикой, `/api` на этот сервис:

```nginx
server {
    server_name hollvpn.online;
    root /var/www/hollvpn/site;

    location / {
        try_files $uri $uri/ =404;
    }

    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

Конфигурация выше проставляет `X-Real-IP`, поэтому в `.env` нужен
`TRUST_PROXY=true`. Без него сервис увидит адрес nginx, не найдёт его
в списке ЮKassa и ответит 403 на все уведомления.

## systemd

```ini
[Unit]
Description=HollVPN checkout
After=network.target

[Service]
WorkingDirectory=/var/www/hollvpn/checkout
EnvironmentFile=/var/www/hollvpn/checkout/.env
ExecStart=/usr/bin/node src/index.js
Restart=always
User=hollvpn

[Install]
WantedBy=multi-user.target
```

## Изменение цен

Цены заданы в двух местах и должны совпадать: `TERMS` в `checkout/src/config.js`
и `CONFIG.subscription.terms` в `site/assets/js/app.js`. Плюс таблица в разделе 4
публичной оферты и позиции в ЮKassa — см. `site/README.md`.
