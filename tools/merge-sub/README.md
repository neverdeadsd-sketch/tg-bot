# Сведённая подписка

Скрипт собирает подписки двух панелей Hiddify в один файл, который бот
раздаёт клиентам как `MERGED_SUBSCRIPTION_URL`.

## Зачем замена

Прежний `/root/merge_sub.sh` искал строки по приметам:

```python
nl_direct = find_line(sub1, ["ss://", "213.193.199.58"])
fi_direct = find_line(sub2, ["vless://", "grpc"])
fi_lte    = find_line(sub2, ["hysteria2://", "fi.hollvpn.ru"])
```

Панели перенастроили на **trojan**, приметы перестали совпадать, и все
`find_line` стали возвращать `None`. Итог — пустой список, пустой
`sub.txt` и **ни одной ошибки**. Клиенты, обновившие подписку после
этого, получали пустой список серверов.

Замена:

- **не знает названий протоколов** — берёт все строки вида `схема://`;
- **не молчит** — недоступная панель, пустой или мусорный ответ, нулевой
  итог означают ошибку с текстом и кодом возврата 1, а прежний файл
  остаётся нетронутым;
- **не содержит ключей** — адреса подписок читаются из отдельного файла.

## Установка

```bash
sudo cp /opt/hollvpn/tools/merge-sub/merge_sub.py /root/merge_sub.py
sudo cp /opt/hollvpn/tools/merge-sub/merge_sub.env.example /root/.merge_sub.env
sudo chmod 600 /root/.merge_sub.env
sudo nano /root/.merge_sub.env
```

В файл впишите два адреса — их видно в старом `/root/merge_sub.sh`,
это две строки `curl`. Прежний скрипт **не удаляйте**, пока новый
не отработает: он пригодится, чтобы сверить результат.

Первый запуск:

```bash
sudo python3 /root/merge_sub.py
```

Он печатает, сколько ссылок нашёл у каждой панели. Если ругается —
читайте текст, он называет причину.

## Проверка

```bash
curl -sk https://213.193.199.58:9443/sub.txt | base64 -d | sed -E 's#(//)[^@]*@#\1***@#'
```

Должны увидеть строки с вашими названиями узлов. `sed` скрывает ключи,
так что вывод можно показывать.

## Расписание

Посмотрите, чем запускался прежний скрипт, и подставьте новый:

```bash
sudo crontab -l | grep -n merge_sub
systemctl list-timers --all | grep -i merge
```

Если запускался по cron — замените в строке `bash /root/merge_sub.sh`
на `python3 /root/merge_sub.py`. Ошибки cron присылает почтой или пишет
в журнал, и теперь им будет о чём сообщить.
