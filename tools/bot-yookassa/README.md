# Оплата через ЮKassa для бота

Готовый модуль: клиент API, хранилище платежей, опрос статуса и выдача
ровно один раз. Он ничего не знает ни про клавиатуры, ни про панель
Hiddify — выдачу ему передают функцией. Поэтому его можно было написать
и проверить, не видя кода бота, и поэтому подключение занимает десяток
строк.

```
payments/
├── yookassa.py   клиент API: создать платёж, прочитать платёж
├── store.py      таблица yk_payments в той же базе, что у бота
├── flow.py       завести заказ и получить ссылку на оплату
└── poller.py     опрос статуса, выдача, тревоги
```

## Почему опрос, а не вебхук

Вебхуку нужен адрес, открытый наружу. На вашем сервере лишний публичный
порт — не то, что стоит заводить ради оплаты, тем более что политика
файрвола сейчас «разрешено всё». Опрос обходится без входящих соединений
вообще: бот сам спрашивает ЮKassa о своих платежах.

## Что он делает правильно

- **Сумму называет сервер.** Клиент присылает срок подписки; цена берётся
  из `config.PRICES`. Подменить сумму нечем.
- **Статус берётся только из API ЮKassa** и сверяется с тем, на что
  выставляли счёт: и значение, и валюта.
- **Подписка выдаётся ровно один раз.** Заказ занимается атомарным
  `UPDATE ... WHERE issued_at IS NULL`; два одновременных прохода опроса
  выдадут один раз, и это проверено тестом.
- **Перезапуск в середине выдачи не теряет заказ.** Занятый, но не
  выданный дольше пяти минут заказ занимается заново.
- **Сорванная выдача не пропадает.** Заказ остаётся оплаченным
  и невыданным, причина записывается, администратору уходит тревога,
  покупателю — честное «оплата прошла, выдаём». Такие заказы видны
  через `store.stranded()`.
- **Ключ идемпотентности — id заказа.** Два нажатия кнопки дают один
  платёж, а не два.

## Тесты

```bash
cd tools/bot-yookassa && python3 -m unittest discover -s test
```

16 проверок, и это не счастливые пути: подменённая сумма, чужая валюта,
повторная выдача, сорванная выдача и повтор после неё, недоступное API,
гонка двух проходов за один заказ, попытка подменить `order_id`
в метаданных.

## Подключение

### 1. Установка

```bash
sudo cp -r /opt/hollvpn/tools/bot-yookassa/payments /opt/tg-bot/app/payments
```

Зависимостей не добавляет: `aiohttp` приходит с aiogram, `aiosqlite`
у вас уже есть.

### 2. В `.env`

```
YOOKASSA_SHOP_ID=139865
YOOKASSA_SECRET_KEY=ключ из кабинета ЮKassa → Интеграция → Ключи API
```

И в `config.py` рядом с остальными:

```python
YOOKASSA_SHOP_ID = _env("YOOKASSA_SHOP_ID")
YOOKASSA_SECRET_KEY = _env("YOOKASSA_SECRET_KEY")
```

### 3. При старте бота

```python
from app.payments import PaymentStore, YooKassa, PaymentPoller

store = await PaymentStore(config.DATABASE_NAME).open()
api = YooKassa(config.YOOKASSA_SHOP_ID, config.YOOKASSA_SECRET_KEY)

async def issue(order):
    # ← единственное место, где нужен ваш код: выдать подписку
    #    order['user_id'], order['days']
    ...

async def tell_user(order, event):
    text = {
        'paid':     'Оплата прошла, подписка активна.',
        'canceled': 'Платёж отменён. Если это ошибка — попробуйте снова.',
        'delayed':  'Оплата прошла. Подписку выдаём, это займёт немного времени.',
    }[event]
    await bot.send_message(order['user_id'], text)

async def alert_admin(text):
    await bot.send_message(config.ADMIN_ID, text)

poller = PaymentPoller(store, api, issue,
                       notify_user=tell_user, notify_admin=alert_admin)
await poller.start()
```

`issue` должна **бросить исключение**, если выдать не удалось. Молчаливый
отказ здесь означал бы принятые деньги без доступа.

### 4. По нажатию «оплатить картой»

```python
from app.payments import create_order

order_id, url = await create_order(
    store, api,
    user_id=callback.from_user.id,
    days=days,
    # ключи PRICES в config.py — строки, здесь нужны числа
    prices={int(k): v for k, v in config.PRICES.items()},
    return_url=f'https://t.me/{BOT_USERNAME}',
)
```

`url` — ссылка на страницу оплаты ЮKassa. Дальше опрос сам заметит оплату
и вызовет `issue`.

## Чего здесь нет

**Чека по 54-ФЗ.** У самозанятого чек формируется в «Мой налог», а не
в ЮKassa, поэтому `receipt` в платёж не передаётся: магазин, не
настроенный на 54-ФЗ, такой платёж просто не создаст. Если статус
изменится, чек добавляется в `payment_body()`.

**Возврата средств.** Отдельная операция API, и её стоит делать руками
до тех пор, пока не понадобится автоматика.
